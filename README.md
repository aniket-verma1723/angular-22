This local role is not sent to the API and is not server authorization. A learner can practice checkout but is denied editor navigation; `/forbidden` offers recovery through login.

Login sends only username, password and `expiresInMins: 30`, then checks `GET /auth/me` with the candidate bearer token. Only matching ID and username publish the minimal user `{ id, username, firstName, lastName, role }`; email, image and other response fields are discarded. No token is displayed. Login plus profile verification has a **15-second total timeout** and an explicit duplicate-operation gate, not an `exhaustMap` implementation. **Verify session** permits one check at a time. **Continue** is an explicit link after login, never an automatic redirect.

Access tokens stay in private in-memory state; logout, expiry and reload end the session. The fixed **30-minute lifetime starts when login begins** and verification does not extend it. Logout cancels login/profile and verification work; an old request's 401 cannot clear a newer token. Password fields clear after success, error, cancellation and destruction while username is kept in the current form. Credentials/tokens are not persisted or logged; auth requests use `credentials: 'omit'`, not cookies. **Refresh is explicitly deferred:** no refresh token is retained, no refresh endpoint is called and no automatic retry occurs.

Bearer attachment is limited to **GET at the exact configured API origin/base path plus `/auth/me`, without query parameters**, checked using `urlWithParams` so `HttpParams` cannot bypass the rule. Other methods/origins, login, refresh, products, carts and image/CDN requests receive no session bearer from this interceptor. This narrow policy does not imply authorization for those public endpoints.

Return paths are restricted to `/dashboard`, `/cart`, `/checkout`, `/products`, `/products/new`, `/products/:id` and `/products/:id/edit` with positive integer IDs. Queries, fragments, outlets, encoded path characters and control characters are rejected; invalid or duplicate `returnUrl` values fall back to `/dashboard`. A guest guard strips the original query before validating the return path. Checkout and editor actions recheck session/role, including after confirmations. Expiry keeps the current draft but blocks new writes; already-dispatched writes are not rolled back. Existing dirty guards remain, so navigating to sign in may ask you to discard a draft.

Mock tokens are runtime-generated, expire after 30 minutes and are bounded to one session per demo user. Reset invalidates them: the next verification receives 401, but reset does not immediately sign out the app or clear its anonymous cart. Read the [P07 implementation record](ANGULAR_22_LEARNING_PROJECT.md#m05--p07-implementation-record--2026-09-27) for store/parser/service/interceptor/guard ownership, Signal Forms integration, cancellation tests and the mock learning path.

## Users, posts and comments (M06 / first P08 slice)

Open `/users` for the searchable Material table. The URL owns `q`, one-based `page` and `pageSize` (10/25/50, default 10). Search trims to 200 characters and applies after 300 ms. Search or page-size changes reset paging; invalid/duplicate parameters normalize safely, defaults and unknown keys disappear. The server supplies the page and total: there is no client-side repaging or sorting of a returned subset, and no directory sort control. Profile links and **Back to users** on the profile retain the validated directory query.

`/users/:id` loads the public profile and posts in parallel, with independent loading/error/retry sections. `/posts/:id` starts post and comments together, then requests the author only after the validated post supplies `userId`. `shareReplay({ bufferSize: 1, refCount: true })` shares that post read between rendering and the author dependency **inside the route-ID switch**, not in a global cache. Each section retries explicitly without reloading unrelated successes; retrying the post also renews its dependent author. ID changes/destruction cancel old reads. Profile-post and comment paging is local, ten rows per page, and resets on parent ID changes; it is not encoded as nested tab routes. Empty collections are distinct from beyond-end pages, which offer first-page recovery. `/posts` itself is a recovery page, not a post directory. The profile now links to `/tasks?userId=<id>`; this is a public assignment link, not a profile tab or session identity.

Services use cold GETs with a **15-second timeout per request**, no automatic retry and no service cache. Shared parsers require safe integer metadata, matching requested offsets, exact expected row counts, distinct IDs and matching relationships. A reduced response limit is valid only when the remaining records fit; empty pages can report limit zero. Minimal projections retain user `{ id, firstName, lastName, image }`, post `{ id, title, body, userId }` and comment `{ id, body, postId, user: { id, fullName } }`. Email, address, password, role and unused fields are discarded even if returned despite `select`; text is interpolated, not inserted as HTML. Missing/broken avatars have named fallbacks; safe image URLs use fixed-size `NgOptimizedImage` rendering.

These public reads omit cookies and receive no session bearer. **No session/auth policy changes**, user/post/comment mutations, storage, dependencies, environment variables or global-tool changes are part of M06. Mock user 1 has 12 posts, post 1 has 12 comments, and user 30 has no posts for paging/empty exercises. Existing mock delay/failure/reset/cancellation rules apply. No live authentication or mutations were performed. ## Tasks (M07 / P08)

Open `/tasks` as a guest, or use a profile's **View this user's tasks** link. The URL owns optional `userId`, one-based `page` and `pageSize` (10/25/50, default 10). An absent filter means all users; an invalid/duplicate/present-empty user ID blocks HTTP rather than silently broadening the query. **All users** is explicit recovery. Paging defaults/unknown keys normalize; filter and page-size changes reset paging. Assignment is public data, never authenticated identity.

The cold data service supports paged `/todos` and `/todos/user/:userId`, detail GET, creation, completion-only PATCH and bodyless DELETE. Each request has a **15-second timeout**, runtime page/identity validation and minimal field projection; no cache or automatic retry. Requests omit cookies and receive no session bearer, including during login; public 401s do not clear the session. The [official todos documentation](https://dummyjson.com/docs/todos) shows `id: "1"` in its PUT/PATCH example. Mutation acknowledgements accept positive safe-integer IDs or canonical decimal strings and normalize to numbers; read IDs and all user IDs remain numeric-only. Extra response fields are discarded and task text is rendered as text.

One component-provided `TaskBoardService` owns each board's signals and **10-operation capacity, including the active write and queued creations**. `concatMap` serializes writes; rows lock immediately on admission and display queued/in-flight state. Completion toggles optimistically between page-local **OPEN / DONE** columns; DELETE keeps its row until a validated success. Inner `catchError` restores only the failing row at its current local position, preserving other rows' successes; creation failure preserves the draft. No write retries automatically. Native **Move up / Move down** and P10 pointer **Drag** reorder within a column without HTTP; completion changes still send PATCH through the same queue. CDK does not supply keyboard dragging: the native buttons remain the keyboard alternative.

P10's typed `CdkDragDrop<readonly TaskRow[], readonly TaskRow[], TaskRow>` handler checks the started row, container identity, previous index and captured board snapshot before `moveToIndex` updates immutable local order. Cross-column, outside, stale, unstarted, invalid and no-op drops do not reorder. Drag requires at least two column rows and is disabled during queued/in-flight writes or confirmations; native moves can still reorder unrelated unlocked rows, but cannot displace pending rows. There is no position field, order endpoint, persistence or extra queue operation. See the [P10 source-reading matrix](ANGULAR_22_LEARNING_PROJECT.md#p10-source-reading-matrix); M07's historical verification below is not verification of this addition.

Signal Forms creation validates non-blank text (200-character UI limit) and a positive safe-integer public assignment ID. Creation results stay separate from the paged rows in both modes; remote-generated IDs have no follow-up actions. Mock-created tasks become actionable only after an explicit read includes them. Totals remain **“at last load”**, not recomputed from local deletes/columns. **Reload page** rereads the server, replaces previews and resets local order/results; browser reload also resets the mock database.

`CanDeactivate` asks before discarding dirty creation drafts, including query-only navigation. Queued/in-flight writes or an open confirmation block departure, URL filter/page changes and reload; reads alone are cancellable. Delete requires confirmation. Dialog cleanup is independent of a cancelled guard subscription. Explicit page reload preserves a dirty creation draft; an accepted query change resets it. Destruction teardown sits **after `concatMap`**: cancel the active request, drop unstarted buffered writes, then reset pending/phase state and complete owned subjects. This does not drain the queue or prove remote rollback; browser unload warnings are best-effort.

The injector-owned task mock has 42 seeds: user 1 has 12, user 2 has three, user 30 has none, and users 3–29 have one each. All 30 users can receive creations. CRUD persists until reset/reload; IDs start at 43 and reset with seeds. Scenarios are consumed on subscription; delays are 0–10,000 ms, with commits only at response time. Cancellation before response prevents a mock commit; reset makes older pending operations fail with 409. Error/malformed/empty-write scenarios never commit; empty lists and missing details remain distinct. Responses are cloned, payloads/parameters allowlisted, unsupported task routes fail locally rather than calling DummyJSON.

**Resources:** no request on entry; Load runs only the selected variant. The RxJS, rxResource and promise variants reuse `ProductsApiService.get`; httpResource sends the equivalent GET through the same configured HTTP pipeline. Public reads omit cookies/session bearer and have a 15-second bound. ID replacement, reload, error recovery and destruction are observable. `httpResource` keeps the same instance across ID changes, parses response shape, then checks identity before publishing; an identity mismatch is a projected UI error, not its raw resource error signal. **Clear destroys and recreates resource instances** to cancel pending reads despite Angular 22.1.7's undefined-parameter abort gap. These are reads, never durable writes.

**Forms:** Signal and Reactive drafts share pure rules, not mutable state, and make **no HTTP writes**. Type a title and blur to commit; controlled availability buttons complete/fail local validation and replacement cancels old checks. Signal Forms uses a defined idle `of(true)` branch so invalid/reset state also replaces the previous validation stream. Save is gated by validity/pending/busy state; **Complete success / Fail response** resolve a manual local simulator. Failure preserves the draft for retry; success/reset clears it.
