Parallel reads, separate recovery

Concept: the profile and its posts are independent reads.

Try it: open another user while requests are pending; retry a failed section without reloading the other.

Angular mechanism: switchMap cancels the old route; combineLatest joins loading, success, and error states, not all-or-nothing results.

Common mistake: waiting for the profile before requesting posts, or keeping the previous user's page.

Revision prompt: why does each read catch its own error?

Tasks: the public assignment link opens the task board with this user's filter, not a profile tab or authenticated identity.
