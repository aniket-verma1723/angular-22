CSS enter/leave and component lifetime

Concept

animate.enter and animate.leave let Angular coordinate CSS classes with insertion and removal. DOM removal is not the same event as component destruction.

Try it

  1. Show the card, then inspect. Hide it and inspect while it fades, then inspect again after the fade. Snapshots change only when you press Inspect animation lifetime.
  2. Use Tab, Enter or Space on the native buttons. Focus stays outside the removable card.
  3. Toggle quickly. If the previous host is still leaving, Show rejects that attempt; try again after removal. There is no queued re-entry or growing collection of cards.
  4. Emulate reduced motion in your browser's Rendering panel and repeat. The same state changes work without movement; there may be no visible leaving interval to inspect.

What Angular does

Angular adds card-enter on insertion and removes that class when the animation finishes. On removal it applies card-leave and waits for the longest relevant CSS animation/transition before removing the host. These are compiler-supported bindings, not legacy animation triggers; no animation provider or JavaScript animation loop is needed.

Older code may use trigger, state, transition and animate from @angular/animations, with an animation provider. Recognize that legacy DSL when maintaining an existing application; this CSS lesson does not install it or mix legacy triggers with the compiler's enter/leave bindings.

When the conditional view is destroyed, the card's DestroyRef.onDestroy callback records whether its host still has a parent. With leave animation enabled it can record attachment even though the Angular instance has already been destroyed. That frozen DOM is not a live component. Inspect again to observe eventual removal separately.

The parent owns the CSS, so it remains available while the child is leaving. Angular owns animation completion and its scheduling/cleanup. The lesson adds no timer, observer, manual listener or subscription. Its only lifecycle callback belongs to the card's destruction scope; no detached elements or per-toggle history are saved.

Common mistake

Do not delay resource cleanup until a CSS event, assume destruction means immediate DOM removal, or leave focus in a disappearing control. Avoid animating layout dimensions for this effect: only opacity and transform change. The reserved stage can still grow for large text.
