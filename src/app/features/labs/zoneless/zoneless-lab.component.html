Zoneless notification lab

One local callback. Two reliable ways to tell Angular that the view has changed.

Concept

OnPush decides which views need checking; scheduling decides when Angular checks. This component uses Angular 22’s default OnPush. A native timer or an imperative EventTarget listener is not, by itself, a zoneless change notification.

Compare a template-read signal with a plain snapshot plus ChangeDetectorRef.markForCheck(). Both modes use the same local event source; neither forces synchronous rendering.

Try it

Choose a notification, then arm one 1,000 ms callback. Wait without clicking anything else. Reset to switch modes or run again. No network, storage, or repeating timer.

What Angular does

  • A changed signal consumed by the template or markForCheck() notifies Angular. The callback finishes without a second Angular button event.
  • Angular-bound template/host listeners also notify. An imperative native listener needs its own bridge.
  • NgZone.run() alone is not a zoneless notification; wrapping a plain assignment is not a fix.
  • Reactive Forms model updates do not automatically schedule a view. Bridge relevant valueChanges, statusChanges, or form events through a template-read signal, AsyncPipe, or a lifecycle-owned markForCheck() subscription.
  • Angular stability does not wait for all native timers. whenStable() waits for Angular’s tracked work, not this delay. Tests first deliver the callback, then await the scheduled render.
  • Test-only Zone.js remains available for the existing Jasmine/Karma suite. These specs explicitly use provideZonelessChangeDetection(); Zone’s presence does not select their rendering strategy.

Common mistake

Assigning a plain field in an external callback and expecting a clean OnPush view to refresh. A later button click can hide the missing notification. This lab keeps both live paths correct rather than deliberately introducing stale bindings. See the reactive state lab for the separate Eager/OnPush contrast; Eager is not polling either.

Cancel, reset, and destruction clear the owned timer. Destruction also removes the native listener; an invalidated callback cannot complete a newer run.
