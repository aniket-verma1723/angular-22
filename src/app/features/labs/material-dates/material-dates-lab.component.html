Material dates and time lab

Throwaway scratch lab: no appointments, persistence, backend requests or unsaved-settings guard. Leaving this lab discards both independent fixtures.

Concept

Compare a Signal Forms single date with a typed Reactive Forms range/time draft. They do not synchronize. A component-scoped NativeDateAdapter uses the fixed display locale en-GB for all three Material controls.

Parser caveat: NativeDateAdapter uses permissive JavaScript Date.parse for typed dates, not a strict en-GB day/month/year parser. Ambiguous numeric text may be misinterpreted or rejected; even a displayed date is not guaranteed to parse back identically. Prefer the calendar. The native time parser is permissive too, not a strict HH:mm validator.

Try

  1. Fill each sample, then open a calendar. Days outside the fixed bounds are disabled.
  2. Type “not-a-date”, then blur. Clear the text or reset to recover to null.
  3. Type “September 20, 2026” as start and “September 15, 2026” as end to inspect reversed-range validation.
  4. Type 08:30 or 17:30 in time and blur. Compare those errors with the bounded 30-minute options.
  5. Use Arrow Down, arrow keys and Enter in time; Escape closes without selection. In a calendar use Alt+Arrow Down to open, arrow keys to move, Enter to select, Escape to close.
  6. Disable a fixture: values remain but controls and toggles stop accepting input. Reset re-enables it, clears values and restores pristine/untouched state.

Mechanism

Material's datepicker is an existing ControlValueAccessor (CVA), and [formField] supports CVAs. This installed version can skip clearing invalid text on a null-to-null reset and miss a same-null parse notification in the direct bridge. Fixture A therefore uses a small CVA-only wrapper: an internal Reactive FormControl forwards Material validation events, and the public Material value setter clears reset text. It does not also implement a Signal Forms control interface; the Signal model remains the fixture owner. Signal minDate/maxDate rules forward bounds metadata through the wrapper, which normalizes accepted values to local calendar days. The independent range parts and timepicker use nullable FormControl<Date | null> controls; Material supplies their parse, bounds and range-order validators. Changing either range endpoint revalidates both controls. Reset also clears raw range text through Material's public value setters. The time CVA resets its value signal but skips formatting while focused, so reset explicitly clears its native text too. Reactive events feed a read-only observation signal.

Mistake

A calendar day is not a UTC instant. These diagnostics use local date getters, not toISOString() or UTC slicing. A timepicker Date is only a carrier for local hours/minutes here; its calendar part is ignored. No timezone, date/time combination or real appointment is inferred. Native parsing can use today's carrier date, and calendars retain Material's real today highlight; neither determines this lab's fixed samples, bounds or initial calendar month.

Revision

Use one owner per fixture; do not mirror the same draft between form systems. Reset is not a save. An empty value is null, while an unparseable input has a validation error even when its model is null (the time CVA can retain an invalid Date). A 30-minute option interval does not enforce typed-time granularity. A production workflow would need an explicit strict parser and timezone/domain policy.
