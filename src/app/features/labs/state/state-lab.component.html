Notifications and lazy computation · S01/S02/S07

Concept

A private writable owner exposes readonly state and semantic actions. Computed values are lazy, memoized and depend only on signals read in the current branch.

Try it

Read twice, increment, read again. Disable the quantity branch, read, increment, then read. Finally compare a nested mutation and equal replacement.

@if (state.observation(); as observation) {

At last explicit read: total {{ observation.result }} · executions {{ observation.executions }} · raw quantity {{ observation.rawQuantity }}

} @else {

Not evaluated yet.

}

What Angular does

The template never reads the instrumented computed. Equal quantity objects do not invalidate it. With the branch disabled, quantity is no longer a dependency after the next read. Re-enable to read the current quantity.

Common mistake

Readonly signals do not deeply freeze objects. A mutation can leave a cached total stale. These new components use Angular 22's default OnPush; the existing root stays Eager. Both checking strategies are independent of P12's zoneless application scheduling. Events, changed inputs and template-read signals notify views; a plain mutation in an arbitrary callback does not. Event-triggered checking may mask mutation bugs, but cannot invalidate a computed cache.

Revision question

Why can raw quantity change while the cached total and execution count do not?

Test observation: dependency removal, equality, stale mutation, immutable recovery and owner isolation have deterministic specs. No detach/detectChanges workaround is added. P12's application-wide zoneless migration is separate from this exercise.

Selection and imperative preview · S03/S04

Concept

linkedSignal lets a user select locally, then resets to the first option when its actual choices source changes. Selection controls the preview radius.

Try it

Selected {{ state.selection() }} · incidental note {{ note() }}

@if (show()) { }
@if (preview(); as result) {

Last inspection: {{ result.runs }} effect runs · {{ result.cleanups }} cleanups · captured {{ result.incidentalNote }}

}

What Angular does

The effect writes one owned CSS custom property through Renderer2, representing a third-party preview integration. Cleanup removes it before rerun and destruction. untracked reads the incidental note without subscribing. Counters are plain instrumentation inspected on demand, not reactive dependencies.

Common mistake

Do not copy derived selection into another signal using an effect. Prefer ordinary style bindings outside this intentional imperative integration.

Revision question

Does changing only the note rerun the effect? When is its newest value captured?

Test observation: actual choice reset, DOM style, incidental dependency exclusion and cleanup are asserted.

State is not an event history · S05/S06

Concept

toObservable observes stabilized state. Outputs represent individual child events. Each toSignal boundary is created once with an explicit initial value.

Try it

@if (show()) { }

Current batch {{ state.batch() }} · last eight stabilized emissions {{ state.emissions().join(', ') }}

{{ state.result() }}

Template output events: {{ templateEvents().join(', ') || 'none' }}

outputToObservable events: {{ observableEvents().join(', ') || 'none' }}

What Angular does

One synchronous burst publishes 3, not an event for every write. The child uses outputFromObservable over counted clicks; the parent receives the actual output both through a template and outputToObservable. Destruction ends subscriptions; recreation starts a new child count. Inner catchError preserves the next success intent.

Common mistake

Do not recreate toSignal in a getter or treat state stabilization as lossless event delivery.

Revision question

Which observation must retain each click, and which only needs the latest state?

Test observation: burst stabilization, initial/error/recovery, real child events and destroyed-child/parent cleanup are covered.

Bounded local debounce · S09; S08 companion

Concept

Angular 22.1.7 debounced is experimental, returning Resource<T>, not Signal<T>. It is not invoked here. This live comparison uses stable RxJS debounceTime with readonly toSignal output.

Try it

Immediate: {{ state.text() || '(empty)' }}

After 250 ms quiet: {{ state.debouncedText() || '(empty)' }}

What Angular does

One stable boundary observes the latest text after a 250 ms quiet period and cancels its timer with the owner. No HTTP or polling occurs.

Common mistake

Debounce does not make a reactive loader suitable for durable writes. S08 resource variants belong to the companion resource lab, not a duplicate implementation here.

Revision question

Why must you verify both stability and the return type before replacing an RxJS helper?

Declaration/test reference: core/types/core.d.ts near line 9544: debounced(source, wait, options?): Resource<T>, experimental 22.0. Specs use fakeAsync virtual time, including replacement and teardown; no experimental runtime or wall-clock waits.
