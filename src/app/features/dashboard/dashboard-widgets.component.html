Concept
Compare independent rendering, latest-value composition and a completed snapshot. None is universally better; choose the behavior the screen needs.
Try it
Load widgets, change strategy, and observe partial progress versus waiting for the snapshot. On a failure, independent and combineLatest retry only that widget; Reload snapshot requests the entire forkJoin group.
Angular mechanism
One toSignal boundary exposes component-owned RxJS state to the template and tears down on destruction. switchMap cancels the previous strategy group. Each combineLatest input starts with loading, so it can show partial progress without waiting for every HTTP response.
Common mistake
forkJoin waits for every input to emit and complete; a never-completing input prevents a snapshot. In RxJS 7, an input completing without any value (EMPTY) makes raw forkJoin complete without a result. Here, an empty stream becomes an error state, while a valid zero-total page is an empty widget. Errors are mapped inside each request before joining, so one failure does not discard healthy results. HTTP services also impose a 15-second response timeout. The first page cannot establish global completion counts.
Revision question
Why seed every combineLatest input with loading, and why must forkJoin recover each request before joining?
