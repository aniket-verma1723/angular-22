Serialize writes, keep recovery local

Concept: concatMap serializes admitted writes; this board caps queued plus in-flight operations at 10. P10 pointer ordering is a separate local interaction.

Try it: toggle different rows and watch queued/in-flight labels, then drag a handle several positions within OPEN or DONE, or use Move up/down: local ordering sends no HTTP.

Angular mechanism: cdkDrag, cdkDragHandle and cdkDropList emit a typed drop event; the board validates the captured snapshot and immutably reorders it. Signals render row state; catchError inside concatMap keeps later writes alive and rolls back only the failed row, not the whole page.

Common mistake: assuming CDK supplies keyboard dragging or persists order. Keep the native Move up/down alternative. Remote writes are simulated; reload rereads the server. Teardown cancels active HTTP and drops unstarted writes, but does not roll back server work.
